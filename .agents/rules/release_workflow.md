# ZiablWinSetup: Правила разработки и релиза (Release Workflow)

## 1. Разделение типов запросов
- **Обычные вопросы / Консультации / Анализ:** Главный агент отвечает напрямую, быстро и ёмко, БЕЗ запуска подагентов.
- **Задачи на доработку / Багфиксы / Подготовку релиза:** Включается многоагентный протокол контроля качества.

## 2. Протокол подготовки релиза
1. **Developer (Основной агент):**
   - Анализирует ТЗ и код. При наличии неоднозначностей или риска для системы — запрашивает уточнение у пользователя.
   - Реализует изменения, обновляет UI, логику, локализацию.
   - Поднимает версию в `app/version.py`, `file_version_info.txt`, `app/ui/index.html`.
2. **QA & Build Tester (`qa-tester`):**
   - Проверяет компиляцию Python (`py_compile`).
   - Запускает сборку бинарного файла через PyInstaller (`ZiablWinSetup.spec`).
   - Проводит смоук-тесты функций.
   - При проверке собранного exe НЕ запускать его с блокирующим ожиданием (`-Wait`) без тайм-аута или завершения процесса (`Stop-Process`), так как это GUI-приложение с постоянным циклом событий и треем.
   - В случае ошибки — возвращает разработчику точный трейсбэк (до 3 итераций исправления). Если блокер непреодолим — эскалация пользователю.
3. **Requirements & Compliance Auditor (`compliance-auditor`):**
   - Сверяет `git diff` с каждым отдельным пунктом запроса пользователя.
   - Проверяет отсутствие упоминаний сторонних брендов (например CCleaner).
   - Проверяет симметричность локализации (`ru` и `en`).
   - В случае расхождений — возвращает разработчику дефекты на устранение.
4. **Финал релиза:**
   - Git commit, создание тега `vX.X.X`, отправка на GitHub (`git push origin main --tags`).
   - Предоставление пользователю структурированного отчёта с чеклистом аудита.
